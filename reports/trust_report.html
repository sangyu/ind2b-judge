Trust report — indication2binder

Graded independently by ind2b-judge · pipeline at commit 3bc41a1 · 2026-09-22

What this is. The pipeline reads a disease name and returns a ranked list of protein targets worth designing a binder against. Those rankings are numbers, and numbers are persuasive — a table of scores looks authoritative whether or not anything supports it. This report is a separate program that re-opens what a run left behind and asks, one claim at a time, whether the run's own output holds up.

Why a separate program. A grader that can call into the pipeline can be made to agree with it. This one imports none of the pipeline's code; its only inputs are the files a run wrote to disk. It cannot ask the system under test what the answer should be, and every pass it reports must cite a specific record — an uncited pass is automatically downgraded, because "looks fine" is what a trust check exists to rule out.

How to read it. The checks are grouped by what they protect: whether the reported numbers faithfully reflect the underlying evidence, whether the findings would survive being run again, and whether the run is honest about what it does not know. A check can also come back not applicable (that stage didn't run) or descoped (the team decided against it) — neither is counted as a pass.

Where the score comes from

Eight weighted components, one multiplicative penalty, and a hard gate. Weights live in a config file rather than in the code, so re-weighting is a config change and not a rewrite. The top-ranked target reconstructs by hand from the published columns:

EGFR  genetic evidence  0.913 × 0.20 = 0.1826
        overall association 0.822 × 0.22 = 0.1808
        approved-drug precedent 1.000 × 0.14 = 0.1400
        antibody tractability 1.000 × 0.10 = 0.1000
        literature 0.992 × 0.10 = 0.0992  ·  clinical precedent 0.932 × 0.08 = 0.0746
        pathway & model 0.827 × 0.06 = 0.0496  ·  expression specificity 0.265 × 0.10 = 0.0265
        sum 0.85323 × 0.92 safety penalty (21 liabilities on record) = 0.78497
Two deliberate choices worth naming. The safety penalty is flat, not per-liability: liability annotations accumulate on targets that have been taken into patients, so compounding it would measure how well-studied a target is rather than how risky. And reachability is a gate, not a term — a binder that cannot reach its target is not a worse binder, so the score is zeroed rather than reduced.

Talking points

Why bother, when the pipeline has its own tests?

Its tests check that the code does what the author intended. This checks whether the output supports what the report claims — a different question, and the one a reviewer actually asks.

What would a failure have looked like?

It found real ones during development. An earlier version of the evidence bridge cited 72 sources that didn't exist; the fidelity checks rejected it. A separate audit found the score treats "evidence nobody fetched" identically to "evidence measured at zero" — both contribute nothing, so a target with no data ranks level with one measured empty.

Is the ranking itself right?

Out of scope, deliberately. This grades process, not biology. It says the numbers trace to their sources and reproduce on re-run — not that EGFR is the correct target for lung adenocarcinoma.

What does the score mean?

Weight of existing evidence, nothing more. Not a probability of success, and not causality. A heavily studied target scores partly on its own popularity, which is why the components are published separately rather than only as a total.

Why did four checks come back not applicable?

These runs stopped after target ranking. The design-job checks — real job, no duplicate GPU billing, honest metrics — have nothing to grade yet, and report that rather than passing by default.

If a demo goes wrong live

A missing artifact makes the run unjudgeable, not incorrect. Silence never scores as success: a run that persisted nothing cannot pass, which is the property the whole exercise rests on.
